If Java had SIGNAL_AND_WAIT semantics, the design can be further simplified. As the program is progressing, the Professor
thread is initially waiting for any signal to occur. As each TA comes up with a question, it begins to wait for other TA's 
to have come up with questions. When a third TA comes up with a question, it would then signal to the 2 waiting TA threads
to wake them, and signal the Professor thread to answer the questions. After the questions are answered (0.5s), the Professor
would then signal the remaining TA threads that the questions have been answered. The TA threads would then again check if 3 TAs 
contain questions, and the process repeats. As the threads are sleeping or waiting for a condition to act, when the last student 
arrives, it would simply utilize SIGNAL_AND_WAIT to signal the Professor  thread that all students have arrived at the university. 
This would then cause the Professor thread to acknowledge that the condition that all students have arrived has been met, and use 
SIGNAL_AND_WAIT to signal the TA and rest of the  Student threads that the condition has been met. This would then cause all the 
threads to print any final lines before terminating.
